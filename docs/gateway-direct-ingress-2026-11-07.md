# 原 CAN0/CAN3 接线：直接交接实测 — 2026-11-07

原接线保持不变，右侧三电机 CAN0、左侧三电机 CAN3。已部署并保留直接交接版本，固定下行 60 B、上行 180 B、125 µs EtherCAT 周期，主站按 1 kHz 更新六条命令。只发送四条 DM 失能帧及两条 DJI 零电流帧，没有执行平衡算法或验证非零力矩。

## 保留的功能路径

- 六个电机反馈直接更新完整最新记录，不再重复入队及重建反馈缓存。
- 板载 IMU 在成功 DMA 完成回调中交接完整样本和紧凑页，线程负责下一次采集启动及恢复。
- HI91 在现有有界 UART 接收回调中校验、裁剪并发布完整页，取消额外消息复制及独立解析线程。
- SBUS 保留单个待确认页，按实际 ESC 写入和匹配 ACK 处理重试，无中间八块队列。
- CAN 准备阶段允许中断；真正请求硬件发送前仍在驱动锁内检查停止、最新命令与 1 ms 提交期限，20 ms 输出/命令保护保留。

协议仍为 DTG1，签名 0x44544731；配套主站 arrival-normal 已匹配。源到达测量 ECAT_SOURCE_ARRIVAL_STATS、HPM_MCAN_RX_TIMING 和 CAN_ISOLATION 均关闭。上位机统计工具仅手动运行，正常固件不采集这些测量。

## 失败试验及恢复

[同一毫秒分散三条命令的候选](gateway-direct-ingress-2026-11-07/can-paced-30s.json) 在约 4.251 ms 触发 CAN 保护，故障码 3，没有形成有效性能数据。具体底层错误尚未定位，不把该结果归因为总线物理极限。该实现与配置已完整撤回，未用作当前版本。

恢复后构建的 bin 与一分钟长测镜像 SHA-256 完全一致，重新刷写并完成 [5 秒复核](gateway-direct-ingress-2026-11-07/restored-5s.json)：交换计数错误均为 0、保护故障码 0、Stop 确认成功。没有以失败候选的短时数据代替正常版本结果。

## 已知约束与后续方向

用户确认终端电阻位于轮电机调速器，取消轮电机移至 CAN1/CAN2 的隔离测试，DTG2 历史准备镜像未部署。用户确认 B 关节约 2 kHz 反馈是驱动器已知软件问题，后续将其作为固定负载，不追查型号或改驱动器参数。六路控制频率保持 1 kHz。

先前源测量记录左轮 CAN SOF 间隔约 1.984–2.032 ms（硬件时间戳粒度 16 µs）。这说明 CAN 源节奏已占用大部分 2 ms 预算，但不能据此把全部主站长尾都归因于驱动器。后续在原拓扑及已知负载下，需要给左轮建立额外裕量；本轮没有通过延迟旧数据或减少命令频率改写统计口径。
