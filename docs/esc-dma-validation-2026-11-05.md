# 2026-11-05 ESC DMA 搬运与缓冲交接验证

**HDMA/XDMA 可以双向访问 HPM5E31 的 ESC PDRAM，尾字节延迟提交和三缓冲交接均通过本轮实板验证。同步等待 DMA 的总耗时没有优于现有 CPU 32 位拷贝；潜在收益需要通过异步流水、独立缓冲所有权与其他工作重叠实现。**

## 环境与方法

- 隔离探针 CONFIG_ECAT_ESC_DMA_PROBE=y，复用根工程的 ESC/SII/PHY；不构造正常网关，不启动 CAN/UART 业务或加热器控制。
- HPM5E31；HDMA6 和 XDMA6，MEMORY_TO_MEMORY、32 位宽、单次 burst=1；DMA IRQ 回调确认完成。
- 未分配 PDRAM 0x4000，长度 8/31/32/128/131/410/512 B。
- 32 位主体由 DMA 搬运，尾部 1～3 B 由 CPU 逐字节处理，不向上取整、不越过 SyncManager 末字节。
- 每个控制器/缓存类型/长度运行 64 组 TX→CPU 校验、RX→CPU 校验；目标边界设 guard，检查未被覆盖。
- 缓存 RAM 源显式 writeback，目标启动前 clean/invalidate、完成后 invalidate；非缓存 RAM 单独验证。启动代码调用 l1c_dc_enable，CONFIG_DCACHE=y。
- 控制字、结果和非缓存传输缓冲位于非缓存段；该段为 NOLOAD，探针启动时显式初始化结果/控制字。
- 基础搬运完成后，PDI 中断关闭，EEPROM 由主循环轮询；没有 SSC 的探针不能让未确认 AL/SM 事件持续触发 PDI 中断。DMA 控制器中断保持开启。
- 上位机正常应用停止，IgH 为 Idle。通过 ethercat reg_read/reg_write 原始物理读写配置和访问 SM，无业务 Arm/OP 握手。

## 数据完整性结果

- 基础双向检查 **1792 组、3584 次 DMA**：两个控制器、缓存/非缓存区域及全部七种长度均正确。
- 数据、guard、DMA 回调错误计数均为 **0**。
- 三轮主站 SM 验证后累计 DMA 回调 **9656 次**，失败仍为 0。
- 本轮验证的是所列尺寸、地址、通道和缓冲方式；没有做长时间并发外设压力或异常断电注入。

## 同一探针中的耗时（us）

| 搬运 | CPU 平均 / 最大 | HDMA 平均 / 最大 | XDMA 平均 / 最大 |
|---|---:|---:|---:|
| RAM→ESC 410 B | 49.72 / 51.71 | 60.08 / 61.17 | 69.18 / 70.46 |
| ESC→RAM 131 B | 19.07 / 26.29 | 29.46 / 31.75 | 30.93 / 32.25 |

表中源/目标使用非缓存缓冲，DMA 每格 64 次、CPU 每格 256 次；计数频率 24 MHz。
CPU 使用现有 hpm_esc_read/write 的 32 位主体＋尾字节路径。
DMA 从配置前开始计时，到 IRQ/信号量唤醒和尾字节处理完成，含配置、启动和等待开销；
不含填充测试图样及启动前的缓存准备。缓存 RX 的完成后 invalidate 包含在对应原始计时中。
本表是独立探针的实际观测值，不是生产循环最坏执行时间保证。

HDMA 预配置后的 reload/start→IRQ 完成：

| 路径 | 次数 | 到 IRQ 平均 / 最大 | 提交函数观测最大 |
|---|---:|---:|---:|
| TX 410 B 主体 408 B | 6048 | 53.68 / 60.04 | 8.00 |
| RX 131 B 主体 128 B | 24 | 25.13 / 26.00 | 5.00 |

IRQ 完成计时尚未包含尾部提交；主体完成不等于镜像已经交给 EtherCAT。
提交函数返回与 IRQ 完成之间存在可供 CPU 执行其他工作的区间，但本轮未测量生产流水线的 CPU 利用率或完整周期改善。

## SyncManager 三缓冲交接

主站设置 SM3=0x1d00/410 B/control 0x20，SM2=0x1100/131 B/control 0x24。
SM2 看门狗关闭，以便人为长时间停在最后几个字节之前；这仅用于本轮隔离测试。
主站处于 Idle，探针显示 INIT/E 是没有 SSC 状态机的预期状态，不能把本结果当作生产 OP/周期 LRW/WKC 验收。

三轮均通过：

1. 上行先用 CPU 发布序号 0 的完整图样，再 DMA 写入下一镜像的 408 B 主体，留最后 2 B。
   主体完成后暂不提交尾部，累计 **192 次**主站读取均仍是旧完整快照；提交尾部后累计 **384 次**读取确认新完整快照。
2. 下行 DMA 读取 128 B 主体，保留最后 3 B。主站在此期间连续写入四个更新镜像。
   完成尾部读取仍得到原快照；释放后下一次读取取得最新镜像。共 **12 组**旧→最新交接全部正确。
3. 双 TX 源缓冲轮转、累计 **6000 次**连续发布；主站做 **234 次**交错读取，所见图样均完整、序号单调，无混合帧。
   主站可跳过中间序号，这是最新值三缓冲语义；本项不要求逐帧交付。
4. DMA 主体完成后源缓冲仍保持占用；尾部提交前的 **6048 次**重复提交尝试均被 EBUSY 拒绝。
   这是单所有者探针的状态保护，不是多线程并发安全性的证明。

## 接入现有网关前仍需处理

- 现有 ESC 读写契约是同步的。异步路径应有显式的提交、完成、尾部交接和缓冲释放状态；不能将同名同步 API 简单改成“启动即返回”。
- DMA 引用的源镜像保持不变；DMA 完成前及尾部提交前不能复用。缓存清理、DMA IRQ 状态、尾部最后一字节与软件发布状态更新的顺序必须明确。
- IRQ 只通知完成，Session/SSC/ESC 交接继续由唯一所有者处理。新镜像可在另一空闲缓冲准备。
- 本轮未验证 DMA 途中 Stop/AL 降级/超时/复位/旧会话完成回调。生产接入需验证 abort 确认及代际隔离；探针超时后保留静态缓冲并停止复用。
- **通道不能直接照搬**：普通固件中 HDMA6/7 属于 UART3；XDMA6/7 属于 SPI3 IMU。隔离探针没有运行这些客户端，所以测试没有冲突。
  接入时需显式预留通道。UART0 不在网关业务别名中且 UART console 关闭，HDMA0/1 可作为重新分配的候选，仍需同步调整 DTS/初始化与资源检查。
- DMA 同步等待在本测试中更慢。因此优先验证 TX 异步流水的实际重叠和端到端延迟，再评估 RX 预取；没有依据承诺仅靠 DMA 满足 125 us。
