# USB 分支整合说明（2026-10-24）

本轮按用户要求将功能分支整合到 usb 和 main；不创建发布标签、不自动刷板。
这表示源码分支整合，不表示已完成当前固件的硬件验收。

## 当前工程

- 单 Zephyr app、多 board；设备选择由 overlay 别名表达，HPM 专属配置位于板卡配置。
- C++ 定义位置、中文注释、模块命名统一；UART/CAN port、USB transport/reports、
  IMU sensor/reports/heater、LED/蜂鸣器按职责组织。
- USB wire v4：CAN 上下行最多六帧；下行固定 128 字节，CAN 上报 40–160 字节，
  其他上报 64 字节。消息结构、编解码与会话策略分离，不保留旧协议头和 client 工具。
- PID 为 UID 的 CRC16，序列号为完整 UID，产品名为 board 名；VID 保留 0x34B7。
- UART11/12/15 已接入；CAN0/1 以空设备表初始化，不开放未知 ID。
- LED/蜂鸣器已接入。IMU 温度继续上报；本地温控目标 45℃，沿用旧 AHRS
  kp=10、ki=0.5（百分比输出、按秒积分），80℃及以上或温度失效时锁存关断。
  板卡配置启用加热，刷入后会自动温控；本轮没有执行刷板。

## 验证与边界

本机协议测试包括 12 个配置测试及禁用异常、ASan/UBSan 的 C++ 合约，固件构建通过。
源目录无遗留旧头文件包含，构建产物与 clangd 统一使用 build/。
GitHub CI 以实际运行结果为准；历史交接中的 v2、旧路径、未提交状态是历史快照。

当前协议需搭配 dust-control v4，不兼容 v2/v3。上位机工作区已经配套修改并通过
8/8 CTest，但本次提交和分支合并仅针对 dust-adapter，不代表上位机改动已提交或推送。
新增接口、UID 枚举、PWM 输出、温控关断及满负载延迟仍须硬件验收。
