# 2026-11-05 ESC TX 异步双缓冲实板对照

**当前原型不适合替代默认 CPU 搬运：循环平均耗时只下降约 3%，CAN 反馈提交年龄增加约 65 μs，状态查询往返增加约 67 μs。缓冲交接与已覆盖的故障退出路径通过本轮检查，但没有证明它是最优方案。实验开关保持关闭，板卡恢复普通 CPU 固件。**

## 实现与台架

- 生产 ABI5，RxPDO 131 B / TxPDO 410 B，主站 125 μs、CPU3、SCHED_FIFO 80；保留首次 Active OP/WKC 不完整即停机的策略。
- 两组均使用同一个 overlay 关闭未用于业务的 UART0，预留 HDMA0；UART3、其他业务串口和 SPI3 IMU 的 DMA 分配保持原配置。
- 两个 448 B 非缓存源缓冲，单个在途＋单个待发；IRQ 只记录完成，SSC 所有者在主站输出处理后、传感器处理后检查完成并写最后 2 B。
- 仅处理 0x1d00/410 B 的生产上行；主体 408 B 由 DMA 搬运。正常队列满进入保护，不覆盖待发缓冲。2 ms 超时、DMA 错误进入 Transport 保护。
- Stop、AL 降级、生命周期重建撤销 DMA 代次，等待硬件 CHEN 清零后才释放缓冲；若 1 ms 内没有停止，冻结缓冲直到 MCU 复位。没有模拟硬件永久卡死，因此不能声称已验证该类故障。
- 测试程序不注册电机命令来源，每次发送检查 source mask 和两个 CAN frame_count 均为 0；正常 UART ACK、IMU、CAN 接收继续工作。右 CAN0、左 CAN3，只统计自发周期反馈的 DJI 0x201；不把无命令时 DM 不回复计为丢帧。
- CPU/DMA 各三轮，每轮 Active 20 s。没有 RTT 周期读取；计时统计仅在停止并执行缓存 writeback 后读取。所有正常轮次完成且主站没有 Active OP/WKC 错误。

## 测量口径

两组都启用专用延迟标记：写尾字节之前将 TX 头 now_us 更新为提交时间，因此 MCU 同一时钟下的 `now_us - capture_us` 是 **CAN 采集到 ESC 提交年龄**，分辨率约 100 μs。它不是主从同步的单向端到端延迟。状态查询 RTT 使用主站同一单调时钟；查询间隔约 5 ms，不发送电机命令。P99 为 25 μs 直方图桶的上边界。

正常循环计时包含 DMA 提交和完成服务。单独的 esc_write_410 在 DMA 下只测入队/启动，不能拿它与 CPU 完整同步写的数值直接当作总搬运加速比。

## 故障与交接验证

| 场景 | 观测 |
|---|---|
| 启动真实 DMA 后立即中止 | 硬件忙中止 +1、占用取消 +1、停止确认失败 0；主站收到保护状态 |
| DMA 主体完成但延迟尾部，保持原 2 ms 截止 | 超时 +1、占用取消 +1、队列溢出 0；主站收到保护状态 |
| 重放旧代次回调 | stale_callbacks +1，继续 Active 满 3 s，正常 Stop |
| 尾部待提交时真实主站 Stop | 占用取消 +1，无超时；正常 Stop，主站收到保护状态 |
| 抑制主站实际发送 | 约 20 ms 后原有陈旧反馈保护停机；没有主站继续发送，不能从接收图像确认从站本地保护触发时刻 |
| PPOR 整片软件复位 | 旧会话因首次 OP/WKC 不完整停止；复位后提交数、代次、在途/待发均为 0；新会话重新 Active 满 3 s 并正常 Stop |

前三个取消占用的场景（忙中止、2 ms 超时、待提交 Stop）都满足：取消时记录的 committed 与退出后的 committed 相同，在途/待发均为 0，没有旧缓冲在取消后继续写尾部。

Stop 测试用专用 hook 将尾部保留窗口延长至 200 ms，并抑制后续测试提交；主站本地看到 3 ms 无新发布后发正常 Stop。该项只验证取消交接，生产 2 ms 超时由独立场景验证。旧回调重放只覆盖软件代次过滤，不代表所有物理总线或中断异常都已验证。

## 排除项与复现

- 一轮正常试验与故障注入重叠，排除并重新运行满 20 s；报告汇总只使用六个完整正常轮次。
- 通用 JTAG `reset run` 的计数器状态不可靠，排除。
- SDK 原始 `reset_soc` SBA 助手在当前访问配置下没有产生可确认的复位，排除。最终使用明确的 32 位 OpenOCD write_memory 写 PPOR 0xf410001c=24000000，事先确认软件复位使能；等待复位后检查零起点计数器并重新握手。
- DMA 计数器在一次启动内累计，第三轮前有排除的故障注入；不要把累计 last_fault 当作第三轮当前故障。主循环计时在每次 Active 重新清零。

源码、构建开关和注入方法见 历史独立探针（正式化时撤下，源码保存在验收归档）。
逐轮计时、延迟、故障前后计数及排除项见 [原始报告 JSON](esc-tx-async-2026-11-05.json)。
本轮结论不推翻 [隔离搬运与 SyncManager 验证](esc-dma-validation-2026-11-05.md)：硬件可完成搬运和交接，但实际循环中的调度、暂存和提交等待抵消了大部分收益，并增加反馈年龄。
