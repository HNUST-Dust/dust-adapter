# 2026-11-05 CAN 快路径与小 PDO 方案

**保持主站 125 μs。已实现并实测的第一阶段只是快慢发布准备分离，仍为 ABI5 的 Rx131/Tx410，不是已完成的小包协议。平均收益有限，实验开关默认关闭；下一阶段布局建议让 CAN 固定在每份小 PDO 中，慢数据附带分段，避免轮流发送纯 CAN/纯传感器包。**

## 第一阶段实现

`CONFIG_ECAT_MULTIRATE_PUBLISH=y`，`CONFIG_ECAT_SLOW_PUBLISH_US=1000`：

- 每次收到输出仍正常解析、校验、分发命令和状态查询，不降低主站交换频率。
- CAN 和状态可每轮更新；UART/IMU 仅在距上次完整发布至少 1 ms 时重新准备。
- 快路径原样保留 UART/IMU 区域，不推进 UART 窗口。IMU 采集、UART 服务没有降频或搬到其他线程。
- 状态改变、非 Active 状态强制完整编码；保护后不保留有效 UART 数据/IMU 标志。重新配置和会话重建清除周期状态。
- 实际慢发布间隔受主循环量化，本轮约 870–895 次/s，不能称为精确 1 kHz。
- 仍由单 SSC 所有者写完整 410 B 到 ESC，因此没有减少 ESC 搬运字节和 EtherCAT 线上的 PDO 字节。

配置见 [实验配置](../config/labs/multirate.conf)，测试见 [说明和合约](../tests/probes/multirate/README.md)。

## 测量与结果

同一台架，主站 CPU3/FIFO80/125 μs，CPU 搬运，两组均关闭 UART0、DMA 关闭；Rx131/Tx410。
本轮新基线 20 s，实验四轮各 20 s，均没有 Active OP/WKC 停机，正常 Stop 观测到保护状态。
试验期间不注册电机命令来源，UART/IMU/CAN 接收继续工作。

两组均在尾字节提交前标记 MCU now_us；CAN 年龄是 MCU 接收时间戳到 ESC 提交，不是同步单向主机延迟。
状态 RTT 用同一主站时钟。分辨率约 100 μs 的 CAN 时间戳只适合以大量样本统计比较。

| 平均值，μs | 新基线 | 快慢分离 |
|---|---:|---:|
| 主循环工作 | 355.75 | 330.24 |
| 右 CAN 采集→ESC 提交 | 296.77 | 284.12 |
| 左 CAN 采集→ESC 提交 | 285.32 | 270.35 |
| 状态查询 RTT | 714.77 | 694.31 |

四轮右 CAN 均值 279.79 / 298.51 / 279.11 / 279.08；左为 265.53 / 286.06 / 264.99 / 264.82；
状态 RTT 为 686.69 / 715.89 / 688.40 / 686.30 μs。第二轮没有改善，不能宣称所有轮次稳定提速。
CAN 年龄各轮 P99 上界仍为 625 μs，没有证明尾部改善。

第二轮调试器 USB 连接断开，未保存 MCU 计时；该轮主站记录仍完整并计入上面的四轮延迟汇总。
追加第四轮后得到第一/三/四轮三份 MCU 计时，330.24 μs 由这三份加权，未伪造第二轮数据。

四轮 UART 块无 discontinuity、主站原始块队列无丢弃；HI91 原始字节流每20s约1.64MB，SBUS约35.7KB。
这不等于验证了 HI91 CRC、完整物理 CAN 交付或长期稳定性。
实验快照 IMU 有效位空缺为0、同一序号内容改变为0。基线的部分 CAN-only 快照不携带有效 IMU，
其含义是该快照不提供 IMU 更新，不应解释成 IMU 物理丢样。保留旧 IMU 快照也不会产生新采样；
本轮 IMU 更新计数是发布序号，不能用来声称物理采集率。主机看到保留样本时应继续依据采集时间判断年龄。

原生 ASan/UBSan 合约通过：快路径原样保留 UART/IMU，诊断与发布序号正常推进，保护/重建后有效标志清除。
默认关闭实验后的普通构建 SHA256 仍为
`142cf1da7ef60197f0d2f82d085c95a2b19dc094c3982e5d01536059f71ec675`。

## 控制优先级更新

用户确认 CAN 与控制用 IMU 同属低延迟关键数据，因此上面的 IMU 1 ms 发布只保留为对照实验，不作为目标方案。
优先验证沿用现有 ABI 的 UART2 128→64 B 块，Tx410→346 B，CAN和IMU仍每轮更新；现有流协议允许HI91跨块重组。
同时必须验证CRC和实际HI91年龄，不能以增加控制IMU等待换取CAN收益。
下面262 B草案不作为已选方案，只有在确认控制IMU不被慢片段延迟后才有讨论意义。

## 早期第二阶段草案：尚未实现或验证

不能将它简单改成 CAN 包、IMU 包、UART 包轮流占用同一个发布机会：这会让 CAN 等待慢数据轮次。
建议先评估以下固定上限的紧凑 PDO，而不是假设 IgH 的固定过程映像能像 USB 一样逐包变长：

| 部分 | 字节预算 | 语义 |
|---|---:|---|
| 会话/时间/状态公共头 | 22 | 每周期都有 |
| CAN0/CAN3 最新反馈 | 132 | 每周期都有，保持每总线3槽 |
| 诊断/请求回复 | 28 | 每周期都有 |
| 慢数据片段描述 | 16 | 类型、端口、序号、采集时间、长度/偏移 |
| 慢数据片段载荷上限 | 64 | UART或IMU，有数据才标记有效 |
| 总上限 | 262 | 相比410 B减少148 B，约36% |

这是布局预算，不是已冻结的线上格式，也不是性能承诺。还需完成两端容量核算、实际输入速率测量及协议评审。
片段公平性、IMU新鲜度、UART有效吞吐都必须以实测和队列上界确认，不能仅从64 B乘交换频率判断可行。

必须成对实现的契约：

1. CAN/状态不等待任何慢片段的重组。所有快字段仍随同一 SM 快照交接。
2. 慢数据带会话、端口、记录序号、采集时间、总长和偏移；主站只交付完整记录。
3. UART保持字节顺序、去重、完整记录ACK和超时；不能以丢弃历史字节实现所谓最新值。
4. IMU完整样本可采用最新值策略，但采集时间、序号与载荷必须一致。
5. Stop、复位和换会话清空两端半包；任何片段都不能影响命令有效期或削弱保护。
6. 修改ABI/签名和双方解码，明确拒绝旧格式，不允许静默兼容。
7. 对比基线须包含全部外设；删除UART/IMU得到的CAN-only短PDO不能当作同负载优化结果。

仅缩短 ESC 拷贝也不足以保证125 μs MCU循环：目前410 B提交在带测量标记的循环内约65 μs，
即使搬运成本按字节线性下降36%，估计也只减少约24 μs，其余SSC、协议处理和传感器调度仍需分析。
该估算不是测量。后续应同时测CAN接收→快照→编码→ESC提交各段等待，避免只追求包长。
